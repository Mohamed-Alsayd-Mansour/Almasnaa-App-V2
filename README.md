# تطبيق المصنع (Almasnaa)

نظام لتنظيم العمل داخل **مصنع أثاث**: تسجيل الغرف وأعداد قطعها، وتسجيل ما يُنتَج منها كل يوم (اليومية)، ثم متابعة النواقص والمشاكل بعد الإنتاج في سجل دائم، مع بحث متقدم واستعلامات تحليلية وطباعة تقارير ومزامنة سحابية مجانية.

التطبيق مبنيّ بـ **Flutter**، واجهته **عربية بالكامل (RTL)** بخط **Cairo**، ويعمل على:

| المنصة | ملاحظات |
|---|---|
| Android | تطبيق APK، واجهة مضغوطة مخصّصة للهاتف |
| iOS | نفس واجهة الهاتف |
| Windows | تطبيق مكتبي، يبدأ بملء الشاشة (F11 للتبديل، Esc للخروج) |
| Web | يعمل في المتصفح بنفس الميزات |

> تبويب **الاستعلامات** متاح على **الويب وويندوز فقط**.

## 1. فكرة التطبيق في دقيقة

- **الغرف**: كتالوج بغرف المصنع (مثال: «أطفال كارما بني ميني») وعدد قطع كل غرفة (خشب، قواطيع، زجاج، رخام).
- **اليومية**: يوم إنتاج واحد. تضيف إليه الغرف التي أُنتجت اليوم، مع النجار والخدمة والرصيص والمشرف والرميم ومكان اللف والترقيم والنواقص والمشكلة.
- **السجل**: أرشيف كل اليوميات. تتابع فيه النواقص، وتعدّلها حتى تكتمل الغرفة، وتبحث وتطبع.
- **الإعدادات**: قوائم الأسماء (نجار، مشرف...)، والنسخ الاحتياطي، والمزامنة السحابية.
- **الاستعلامات** (ويب/ويندوز): تقارير وتحليلات على كل البيانات، مع تدقيق آلي للتناقضات.

كل البيانات تُحفظ **محليًا على الجهاز** (بلا خادم) ويمكن مزامنتها عبر مستودع GitHub خاص.

## 2. دورة العمل

```
   الغرف                 اليومية                  السجل
 (الكتالوج)   ──►   (يوم إنتاج نشط)   ──►   (أرشيف + متابعة النواقص)
 أعداد القطع        إضافة غرف + بيانات         بحث + تعديل + طباعة
                    إنهاء اليومية ───────────►  تتحول إلى «مغلقة»
```

1. أضف الغرف في تبويب **الغرف** (مرة واحدة، وعدّلها متى شئت).
2. في **اليومية** اضغط «بدء يومية»، ثم «إضافة غرفة» لكل غرفة أُنتجت.
3. عند انتهاء اليوم اضغط «إنهاء اليومية وإضافة للسجل». لا يُحذف شيء: تتحول اليومية إلى `مغلقة`.
4. من **السجل** تابع الغرف التي بها نواقص، وعدّل النواقص عند استكمالها، وابحث وافلتر وانطبع.

لا يمكن وجود **أكثر من يومية نشطة** في وقت واحد.

## 3. مفاهيم أساسية

### 3.1 ملكية الغرفة (داخلية / خارجية / أوردر)

عند إضافة غرفة لليومية تختار **ملكية الغرفة** عبر ثلاثة أزرار:

| النوع | مصدر الاسم والعدد | الحقول الإلزامية | الحقول المعروضة |
|---|---|---|---|
| **داخلية** | تختار غرفة من كتالوج «الغرف»، والعدد الكلي يُؤخذ تلقائيًا منها | الغرفة، الترقيم، النجار | كل الأسماء + الزبون (اختياري) + التاجر (اختياري) |
| **خارجية** | تكتب اسم الغرفة وعددها يدويًا (غرفة ليست في الكتالوج) | الاسم، الترقيم، **التاجر**، العدد | التاجر فقط بدل النجار والخدمة والرصيص والمشرف والرميم، + مكان اللف |
| **أوردر** | تكتب **وصف الأوردر** وعدد القطع يدويًا | الوصف، الترقيم، العدد، **النجار**، و**اسم الزبون أو التاجر (أو كلاهما)** | كل الأسماء + الزبون + التاجر |

- **الأوردر** = طلب مخصوص لزبون. لا يدخل كتالوج الغرف، ولا يحتمل وسم «مواصفات» ولا «جزء من غرفة».
- اسم الأوردر في الجداول: `أوردر (عدد القطع) - اسم الزبون`، وإن لم يُكتب زبون فاسم التاجر.
- **اسم الزبون** و**اسم التاجر** حقلان مستقلان تمامًا.
- الغرفة الخارجية تُعرض في الجداول بعلامة `- خارجية`.

### 3.2 غرفة كاملة / جزء من غرفة

لغير الأوردر تسأل النافذة «هل الغرفة كاملة؟»:

- **كاملة**: عدد القطع هو العدد الكلي للغرفة.
- **جزء منها**: تكتب **اسم الجزء أو الأجزاء** (مثال: `2سرير وكمود`) و**عدد القطع الموجودة**.
  - يُسجَّل الاسم بصيغة `[الجزء] [الغرفة]`، ويُحسب عدد القطع من «عدد القطع الموجودة».
  - في الغرفة الخارجية الجزئية يُؤخذ العدد من «عدد القطع الموجودة» نفسه فلا يُسأل عن عدد مكرر.

### 3.3 وسم «مواصفات»

غرفة بمواصفات وتعديلات شكلية خاصة. عند تفعيله تظهر خانتان:

- **المواصفات والتعديلات الشكلية** (نص حر).
- **عدد قطع غرفة المواصفات**: **مستقل تمامًا** عن العدد القياسي للغرفة. عند التفعيل يُملأ تلقائيًا بالعدد الحالي كنقطة بداية فقط، وتعديله لا يؤثر على العدد القياسي المحفوظ، والعكس.

الغرفة بهذا الوسم تُعرض: `الاسم - مواصفات (العدد)`.

### 3.4 النواقص وحسابها

حقل **نواقص الغرفة** نص حر، تفصل بين القطع الناقصة بعلامة `-`:

```
باب - رف علوي - ضلفة يمين      ⇒  عدد الناقص = 3
(فارغ)                          ⇒  0
```

القاعدة (في `lib/utils/deficiency_calculator.dart`): نص فارغ = 0، وإلا فعدد علامات `-` زائد واحد. العدد **محسوب دائمًا** ولا يُدخل يدويًا في أي مكان.

### 3.5 الحالة

- **مكتملة** (أخضر شفاف): النواقص الحالية فارغة.
- **بها نواقص** (أحمر شفاف): النواقص الحالية غير فارغة.

الحالة **مشتقة من نص النواقص الحالي** دائمًا وليست قيمة مخزّنة يمكن العبث بها.

### 3.6 النواقص الأصلية مقابل الحالية

لكل إدخال نسختان:

- **الأصلية**: كما سُجّلت وقت الإنتاج، ولا تتغير من الجداول.
- **الحالية**: يمكن تعديلها من السجل واليومية مع تسجيل وقت آخر تعديل.

وبذلك يمكن تحليل «كم قطعة استُكملت بعد الإنتاج» (الأصلي − الحالي).

### 3.7 المشكلة

حقل نص حر بعد النواقص يوضح **سبب القطع الناقصة**.

### 3.8 الأشخاص (قوائم الأسماء)

ستة أدوار، لكل دور قائمة أسماء مستقلة تظهر كخيارات عند تسجيل غرفة:

`الخدمة` · `النجار` · `الرصيص` · `المشرف` · `الرميم` · `مكان اللف`

## 4. القواعد الجوهرية

- **Snapshot عند التسجيل**: اسم الغرفة وعدد قطعها يُنسخان داخل الإدخال لحظة إضافته. تعديل الغرفة أو حذفها لاحقًا **لا يغيّر** أي سجل قديم.
- **تكرار الغرف مسموح**: يمكن إضافة نفس الغرفة أكثر من مرة في نفس اليومية؛ كل إدخال وحدة إنتاج مستقلة له معرّف خاص.
- **إغلاق اليومية لا يحذف شيئًا**: يبقى كل شيء مقروءًا ومعدَّلًا من السجل.
- **يومية نشطة واحدة** فقط في أي وقت.
- **حذف اسم من قوائم الأسماء** لا يؤثر على السجلات المسجّلة سابقًا.
- **التعديل الشامل** في السجل محميّ بكلمة مرور (انظر 5.3).
- **توافق البيانات القديمة**: كل حقل جديد له قيمة افتراضية عند غيابه في البيانات المخزّنة، فلا تتعطل السجلات القديمة. الأوردر القديم (قبل فصل الزبون عن التاجر) يُنقل اسمه تلقائيًا إلى «اسم الزبون» عند القراءة.

## 5. شرح الشاشات

بعد شاشة البداية (Splash) المتحركة (نحو 2.2 ثانية) تظهر الشاشة الرئيسية بتبويبات: **الغرف / اليومية / السجل / الإعدادات / (الاستعلامات)**.

### 5.1 تبويب الغرف

جدول الغرف مع بحث نصي وأزرار الإضافة والطباعة.

| العمود | المعنى |
|---|---|
| م | الترتيب |
| الغرفة | الاسم |
| قطع الخشب | |
| قطع القواطيع (عددها) | مثال `1 (11)`: عدد قطع القواطيع ثم عدد القواطيع نفسها بين قوسين |
| قطع الزجاج | |
| قطع الرخام | |
| عدد القطع الكلي | خشب + قواطيع + زجاج + رخام |
| عدد ورق الطباعة | خشب + قطع القواطيع |
| تعديل | تعديل / حذف |

- نافذة الإضافة/التعديل تعرض الإجماليين محسوبين لحظيًا.
- **عدد قواطيع الغرفة** للعرض فقط ولا يدخل في أي مجموع.
- التحقق: الاسم مطلوب، وقطع الخشب أكبر من صفر، وباقي الأعداد غير سالبة.
- حذف الغرفة لا يؤثر على السجلات التاريخية (Snapshot).
- زر **طباعة الغرف** (غير موجود في تطبيق أندرويد) بقوالب جاهزة: التقرير الكامل، تقرير القطع، تقرير ورق الطباعة.

### 5.2 تبويب اليومية

**بدون يومية نشطة**: شاشة فارغة بزر «بدء يومية» (تُنشأ بتاريخ ووقت الآن واسم اليوم بالعربية).

**مع يومية نشطة**: رأس يعرض اليوم والتاريخ ووقت البدء والانتهاء، وجدول الغرف وأزرار «إضافة غرفة» و«طباعة اليومية» و«إنهاء اليومية وإضافة للسجل».

أعمدة الجدول:

`م` · `الغرفة (القطع)` · `الترقيم` · `النجار` · `الخدمة` · `الرصيص` · `المشرف` · `الرميم` · `التاجر` · `اسم الزبون` · `مكان اللف` · `المواصفات` · `وصف الأوردر` · `النواقص` · `المشكلة` · `عدد الناقص` · `إجراءات`

- **تعديل لحظي مباشر** بالضغط على الخلية: **النواقص** و**المشكلة** و**المواصفات** (للغرف ذات الوسم) و**وصف الأوردر** (للأوردر). كل منها يفتح نافذة صغيرة بحفظ فوري.
- زر التعديل يفتح نافذة تعديل بقية الحقول التشغيلية؛ زر الحذف يحذف الإدخال من اليومية بعد تأكيد.
- نافذة الإضافة تتغير حقولها حسب الملكية (انظر 3.1)، وتتحقق من: الترقيم، وكون النجار إلزاميًا للداخلية والأوردر، والتاجر إلزاميًا للخارجية، والزبون أو التاجر للأوردر، واسم الجزء وعدده للغرفة الجزئية، وعدد قطع المواصفات غير سالب.

### 5.3 تبويب السجل

يعرض **كل** إدخالات **كل** اليوميات (نشطة ومغلقة) مرتبة من الأحدث إلى الأقدم.

**الأعمدة**: م · اليوم · التاريخ · الغرفة (القطع) · الترقيم · النجار · الخدمة · الرصيص · المشرف · الرميم · التاجر · اسم الزبون · مكان اللف · المواصفات · وصف الأوردر · النواقص · المشكلة · عدد الناقص · الحالة · تعديل.

**البحث الشامل**: خانة واحدة تبحث في: اسم الغرفة، الترقيم، كل الأسماء (النجار/الخدمة/الرصيص/المشرف/الرميم/مكان اللف)، المواصفات، النواقص (الأصلية والحالية)، المشكلة، اسم الجزء، التاجر، الزبون، اسم اليوم، وأعداد القطع والنواقص.

**البحث المتقدم** (زر الفلتر) بفلاتر تجتمع معًا:

| الفلتر | القيم |
|---|---|
| من تاريخ / إلى تاريخ | نطاق زمني |
| اسم الغرفة، النجار، الرصيص، المشرف | نص يطابق جزءًا من الاسم |
| مكان اللف | قائمة اختيار |
| حالة الغرفة | الكل / مكتملة / بها نواقص |
| شكل الغرفة | الكل / عادية / مواصفات / جزء من غرفة (على الهاتف: «جزء») |
| **ملكية الغرفة** | الكل / داخلية / خارجية / أوردر |

الفلاتر المفعّلة تظهر كشرائح (Chips) فوق الجدول، وزر «مسح الفلاتر» يزيلها.

**التعديل المباشر**: النواقص والمشكلة والمواصفات ووصف الأوردر قابلة للتعديل بالضغط على الخلية.

**التعديل الشامل** (زر لكل صف): يعدّل **كل** حقل في الإدخال بما فيه الأصلية والحالية من النواقص، وعدد القطع، وأسماء الأشخاص، والجزء، والمواصفات. محمي بكلمة مرور تُطلب مرة وتبقى مفتوحة حتى «قفل التعديل الشامل»:

> كلمة المرور الافتراضية: `0000` — قيمتها الثابتة `kRecordsEditPassword` في `lib/utils/password_gate.dart`. **غيّرها** قبل الاستخدام الفعلي، وهي حماية واجهة بسيطة فقط وليست تشفيرًا.

عند تعديل أي من نص النواقص (الأصلي/الحالي) يُعاد حساب العدد المقابل تلقائيًا.

### 5.4 تبويب الإعدادات

1. **البيانات والنسخ الاحتياطي**
   - **تصدير**: يحفظ كل البيانات في ملف JSON.
   - **استيراد**: يقرأ ملف JSON، ويتحقق منه تحققًا كاملًا (البنية، الإصدار، صلاحية كل سجل) **قبل** أي كتابة، ثم يعرض ملخصًا (عدد الغرف واليوميات والإدخالات والأسماء) ويطلب التأكيد ويستبدل البيانات الحالية.
   - **حذف جميع البيانات**: يتطلب كتابة كلمة «حذف» للتأكيد، مع خيار حذف قوائم الأسماء أيضًا.
2. **قوائم الأسماء**: إضافة وتعديل وحذف الأسماء لكل دور (6 أدوار).
3. **المزامنة السحابية** (انظر القسم 7).

### 5.5 تبويب الاستعلامات (ويب وويندوز فقط)

بحوث وتجميعات على **كل** البيانات، بتطبيع عربي للبحث (يتجاهل التشكيل والتطويل، ويوحّد الألف والياء والتاء المربوطة والأرقام الهندية)، وبحث متعدد الكلمات (كل كلمة يجب أن تظهر في أي حقل).

**العروض التسعة**:

| العرض | ماذا يعرض |
|---|---|
| ملخص عام | مؤشرات: الغرف، اليوميات، الإدخالات، القطع المنتجة، نسبة الاكتمال، ملاحظات التدقيق، وأفضل الأسماء |
| الغرف | كل غرفة: مرات إنتاجها، نسبة اكتمالها، آخر إنتاج |
| اليوميات | كل يومية: مدتها، عدد الغرف والقطع، نسبة الاكتمال |
| السجلات | كل إدخال بتفاصيله؛ الضغط على صف يفتح تفاصيله |
| تجميع الإنتاج | إحصاءات مجمّعة حسب: الغرفة، النجار، الخدمة، الرصيص، المشرف، الرميم، مكان اللف، التاجر، اليوم، التاريخ، الشهر، الحالة، الشكل |
| النواقص المتكررة | كل قطعة ناقصة: كم مرة نقصت وكم استُكمل ومن الأكثر ارتباطًا بها |
| المشاكل | المشاكل مجمّعة حسب النص مع الغرف المتأثرة |
| الأسماء | أداء كل اسم: إنتاجه ونسبة الاكتمال والنواقص المرتبطة |
| تدقيق البيانات | فحص آلي للتناقضات (انظر أدناه) |

**الفلاتر**: بحث نصي، الحالة، الشكل (عادية/مواصفات/جزء من غرفة)، **ملكية الغرفة**، الغرفة، اليوم، نطاق التاريخ، فلتر لكل دور (النجار...)، «بمشكلة مسجلة فقط»، «نواقص معدّلة بعد الإنتاج». ويمكن طباعة أي نتيجة بقالب مخصص.

**فحوصات التدقيق الآلي** (بمستويات خطورة عالية/متوسطة/منخفضة):

- إدخال: يومية غير موجودة، عدد قطع صفر، عدد الناقص المخزّن لا يطابق النص (حالي/أصلي)، النواقص زادت عن الأصلية، الناقص أكبر من عدد القطع، مشكلة على غرفة مكتملة، نواقص بلا مشكلة، مواصفات بلا نص أو عدد، جزء بلا اسم أو عدد أو أكبر من الغرفة، خارجية بلا تاجر، الغرفة الأساسية محذوفة، الاسم أو العدد القياسي لا يطابق كتالوج الغرف، بيانات ناقصة، اسم غير مسجل في الإعدادات، إدخال مكرر محتمل، ترقيم مكرر في اليومية.
- يومية: نشطة لم تُغلق بعد مرور تاريخها، مغلقة بلا وقت انتهاء، الانتهاء قبل البدء، بلا إدخالات، اسم اليوم لا يطابق التاريخ، أكثر من يومية في نفس التاريخ.

## 6. الطباعة والتقارير

الطباعة تعتمد على **تقارير HTML**: يُبنى التقرير ويُحفظ في مجلد مؤقت ثم يُفتح في المتصفح الافتراضي لتطبع منه أو تحفظه PDF.

- **أين**: من الغرف، واليومية، والسجل، والاستعلامات (زر الطباعة غير ظاهر في تطبيق أندرويد).
- **قوالب جاهزة** للسجل واليومية: **التقرير الكامل** (كل الحقول)، **تقرير التخزين**، **تقرير المصنع**؛ وللغرف: الكامل، القطع، ورق الطباعة.
- **قوالب مخصصة**: «تخصيص قالب» لتسمية القالب، واختيار الاتجاه (أفقي/عمودي A4)، واختيار الحقول وترتيبها بالسحب. تُحفظ محليًا، ولكل مجموعة بيانات (الغرف/السجل/كل استعلام) قوالبها المستقلة؛ ويمكن استخدامها وتعديلها وحذفها.
- **المعاينة**: قبل الفتح تظهر معاينة بعدد السجلات والاتجاه.
- **العنوان**: `سجل الغرف (اسم القالب)` بدون كلمة «تقرير».
- **حقول السجل المتاحة** (23 حقلًا): الغرفة (القطع)، مواصفات، جزء من غرفة، اسم الجزء، عدد القطع، العدد القياسي، عدد قطع المواصفات، الترقيم، النجار، الخدمة، الرصيص، المشرف، الرميم، اسم التاجر، اسم الزبون، غرفة خارجية، مكان اللف، نص المواصفات، وصف الأوردر، النواقص، المشكلة، عدد الناقص، الحالة، اليوم، التاريخ، حالة اليومية.
- أماكن التخزين المؤقت للتقارير: ويندوز `%LOCALAPPDATA%\Almasnaa\Reports`، وغيره داخل المجلد المؤقت للتطبيق؛ وتُنظَّف التقارير القديمة تلقائيًا.

## 7. النسخ الاحتياطي والمزامنة السحابية

### 7.1 النسخة الاحتياطية (ملف JSON)

```json
{
  "app": "almasnaa",
  "version": 1,
  "exported_at": "...",
  "data": { "rooms": [], "sessions": [], "entries": [], "people": [] }
}
```

يرفض الاستيراد: الملف غير JSON، أو ليس نسخة «المصنع»، أو إصداره أحدث من التطبيق، أو ناقص قسمًا مطلوبًا، أو فيه سجل غير صالح. قسم `people` اختياري لدعم النسخ القديمة.

### 7.2 المزامنة مع GitHub

تخزّن نسخة JSON كاملة في الملف `cloud-sync/almasnaa-data.json` داخل مستودع تحدده، عبر **GitHub REST API**، **يدويًا** (رفع / تنزيل) وليس تلقائيًا.

**الإعداد الموصى به:**

1. أنشئ مستودعًا **Private** مخصصًا لبيانات التطبيق.
2. أنشئ **Fine-grained Personal Access Token**.
3. اجعل **Repository access** مقتصرًا على هذا المستودع فقط.
4. امنحه صلاحية **Contents: Read and write** فقط.
5. أدخل اسم المستخدم واسم المستودع والرمز داخل التطبيق (الإعدادات ← المزامنة السحابية).
6. **اختبار الاتصال** للتأكد من الوصول قبل الرفع.
7. **رفع** من الجهاز صاحب البيانات الأصلية، ثم **تنزيل** على أي جهاز آخر.

**الأزرار**: الرفع · التنزيل · الاختبار · الحفظ · مسح بيانات الاتصال. ويظهر وقت **آخر مزامنة** ناجحة. التنزيل يعرض ملخصًا ويطلب التأكيد قبل استبدال البيانات الحالية.

**الأمان:**
- الرمز يُحفظ **محليًا على الجهاز فقط**، ولا يدخل ملف النسخة الاحتياطية، ولا يُمسح بـ «حذف جميع البيانات».
- إن كان المستودع **عامًا (Public)** فإن ملف البيانات يمكن أن يقرأه أي شخص. استخدم مستودعًا **خاصًا** دائمًا.
- حالات الخطأ (رمز خاطئ، مستودع غير موجود، تعارض الإصدار `sha`) تُعرض برسائل عربية مفهومة.

## 10. نموذج البيانات

`id, name, piece_count (خشب), glass_piece_count, partition_piece_count, partition_count, marble_piece_count, created_at, updated_at`

`id, day_name, date, start_time, end_time?, status (active | closed)`

| المجموعة | الحقول |
|---|---|
| الهوية | `id`, `dailySessionId`, `roomId?` (قد تصبح null إن حُذفت الغرفة) |

| التشغيل | `numbering`, `carpenter`, `service`, `installer`, `supervisor`, `repairer`, `wrapLocation` |

`id, name, role, created_at`

## 12. ملاحظات معروفة

للأمانة، هذه نقاط موجودة في المشروع حاليًا وتستحق الانتباه:

1. **كلمة مرور التعديل الشامل ثابتة** (`0000`) في الكود. غيّرها قبل الاستخدام الفعلي.
2. **ملفات قديمة غير مستخدمة**: `lib/services/excel_export_service.dart` و`lib/services/daily_print_service.dart` و`lib/widgets/export_fields_dialog.dart` بقايا من تصدير Excel/PDF قبل استبداله بطباعة HTML. لا يستورد أي ملف نشط أيًّا منها، وتعتمد على حزم (`excel_community`, `pdf`, `printing`) **غير معرَّفة** في `pubspec.yaml`، لذا قد يُظهر `flutter analyze` أخطاء عنها دون أن يتأثر البناء. يمكن حذفها بأمان أو إضافة الحزم إن أُريد إحياؤها.
3. **ملف الاختبار القديم** `test/widget_test.dart` هو قالب Flutter الافتراضي (يشير إلى `MyApp` غير الموجود)، فيفشل `flutter test` حاليًا.
4. **أسماء المنصات الافتراضية**: عنوان صفحة الويب (`hello_world`) واسم العرض في iOS (`Hello World`) ومعرّف حزمة أندرويد (`com.example.almasnaa`) ما زالت قيم القالب الافتراضية.
5. **وسم زر الطباعة**: غير متاح في تطبيق أندرويد بقرار تصميمي.
6. **التخزين محلي**: مسح بيانات المتصفح أو التطبيق يمسح البيانات؛ استخدم التصدير أو المزامنة السحابية بانتظام.
7. **المزامنة يدوية** وتستبدل البيانات كاملةً (لا دمج)، فلا تعمل على جهازين بالتوازي دون الرفع/التنزيل بالترتيب الصحيح.
8. التعديلات الأخيرة على واجهة الهاتف (شريط الحالة والتخطيطات) كُتبت دون بناء وتجربة على جهاز، فتستحق مراجعة بصرية.
