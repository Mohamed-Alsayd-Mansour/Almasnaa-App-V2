# المرحلة 3 — ربط التطبيق بـ Supabase، اليوميات المتعددة، المزامنة اللحظية

## خطوات التشغيل
1. شغّل `supabase/migrations/0005_phase3_entry_guard.sql` في SQL Editor (تغيير صغير: الغرف الخارجية تبقى بأسماء رصيص/مشرف فارغة كما في 1.0، مع نسبتها بالمعرّف).
2. `flutter pub get && flutter analyze && flutter test` ثم ابنِ كالمعتاد (لا حزم جديدة).
3. أول تشغيل بعد التحديث يمسح تلقائيًا إعدادات المزامنة القديمة من الجهاز (ومنها رمز GitHub). بيانات 1.0 المحلية **لا تُحذف**.

## ما تغيّر
- **الخادم مصدر البيانات الوحيد**: الغرف، الأسماء، اليوميات، الإدخالات، السجل والاستعلامات كلها تُقرأ/تُكتب في Supabase (المستودعات أُعيدت كتابتها بنفس واجهة 1.0 فلم تتغير الشاشات إلا للصلاحيات). لا كتابة محلية بديلة؛ عند انقطاع الإنترنت تظهر رسالة صريحة ولا يُدّعى الحفظ.
- **اليوميات المتعددة (الرصيص)**: مبدّل أعلى تبويب اليومية يعرض يومياته المفتوحة (مختارة/معلّقة) باسم المشرف والتاريخ. التبديل يعلّق السابقة دون إغلاقها. تغيير المشرف يستأنف اليومية المفتوحة معه أو ينشئ واحدة جديدة، ولا تتكرر عند الضغط المتكرر (دوال الخادم ذرّية). الإنهاء صريح فقط، وبعده تصبح اليومية سجلًا تاريخيًا.
- **المشرف**: يرى اليوميات المسندة إليه (وما فيها من إدخالاته فقط)، بلا إضافة غرف وبلا إنهاء يومية. **الأدمن**: يرى الكل.
- **المزامنة اللحظية**: Realtime على الجداول، تحديث هادئ بلا وميض، إعادة مزامنة عند عودة الاتصال وتحديث احتياطي كل دقيقتين. مؤشر في شريط التطبيق (متصل / جارٍ الاتصال / غير متصل + آخر مزامنة). **لا أزرار مزامنة يدوية**. حذف خدمة GitHub من العميل (كانت تخزّن PAT على الجهاز).
- **الإعدادات**: النسخ الاحتياطي عبر دوال الخادم وبكلمة مرور مستقلة (تصدير للجميع باسم `almasnaa-data-{الرصيص}-{المشرف}.json`، واستيراد وحذف جماعي للأدمن فقط مع ملخص وتأكيد وكتابة ذرّية). بطاقة المزامنة للقراءة فقط. قسم الربط (الرصيص يغيّر مشرفه، المشرف يرى رصيصيه، الأدمن يرى الكل ويغيّر). قوائم الأسماء: الأدمن والمشرف يعدّلان، الرصيص قراءة فقط (وأُخفيت قائمتا «الرصيص» و«المشرف» لأنهما صارا من الحسابات).
- **السجل**: الرصيص يعدّل 4 حقول مباشرة فقط (يفرضها الخادم) ولا يرى زر «تعديل شامل». المشرف والأدمن تعديل شامل. **أُزيلت كلمة المرور الثابتة `0000` من الكود** (صلاحية الخادم بدلها).
- **إشعارات**: جرس بعدّاد غير المقروء وقائمة تُحدَّث لحظيًا (تولّدها قاعدة البيانات لكل إضافة/تعديل/حذف لأدمن + الرصيص والمشرف المعنيين، ولا يتلقى المنفّذ إشعار عمليته).
- عند الخروج أو تعطيل الحساب تُفرَّغ كل بيانات الذاكرة، فلا تظهر بيانات مستخدم سابق للتالي.

## الاختبارات
- قاعدة البيانات (PostgreSQL 16 محلي): **107 اختبارات ناجحة** (منها 9 جديدة: الغرف الخارجية، إعادة المحاولة بنفس المعرّف بلا تكرار، وقت الخادم، تعديل جزئي، قيود الرصيص بعد الإغلاق، رؤية المشرف لليومية المفتوحة).
- Flutter: أُضيف `test/data_layer_test.dart` (تحويل الأوقات UTC/محلي، اليومية المعلّقة، رسائل الأخطاء) بجانب اختبارات المرحلة 2.

## لم يُنفَّذ / لم يُتحقق منه (بصراحة)
- **لم أستطع تشغيل `flutter analyze/test/build`** هنا (لا Flutter ولا pub.dev). فحصت الأقواس والواردات آليًا وراجعت الواجهات يدويًا فقط. شغّل CI وأرسل لي المخرجات.
- لم تُختبر على Supabase الحقيقي: Realtime، والـ embed في الإشعارات (`audit:audit_log(...)`)، وحفظ الملفات على المنصات. ملاحظة: قد يتطلب Realtime تفعيل الجداول في Dashboard → Database → Replication إن لم تكن مضافة.
- **مؤجل للمرحلة 4**: وضع «عرض كمستخدم» للأدمن، المحادثات والمرفقات و@، فتح السجل من الإشعار، أرشفة GitHub من الخادم (كانت v1 تعتمد PAT في العميل؛ لا بديل بعد)، وخيار «حذف الأسماء فقط» القديم (الحذف الجماعي الآن يشمل كل البيانات التشغيلية).
- استيراد ملفات 1.0 من الواجهة غير مدعوم عمدًا (التحويل بسكربت الترحيل). تقارير الاستعلامات تعمل على بيانات المستخدم المسموحة (الأدمن: الكل) وتحمّلها كلها في الذاكرة (مناسب لمئات/آلاف الصفوف).
