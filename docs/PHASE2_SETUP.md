# المرحلة 2 — الهوية والأدوار وتبويب الأدمن

## ما أُضيف
- **الدخول**: الدور ← اسم المستخدم (قائمة النشطين فقط حسب الدور) ← كلمة المرور. رسالة الفشل عامة لا تكشف أيهما الخطأ. زر الدخول يُعطَّل أثناء الطلب.
- **كلمات المرور الأولية**: كلها 6 أحرف بصيغة `@الرقم@` (طلبك). تُمرَّر عبر `.env` إلى `scripts/migrate_v1.py` ولا تُحفظ في أي ملف. الأدمن مُلزَم بتغيير كلمته عند أول دخول (6 أحرف على الأقل).
- **الرصيص**: بعد الدخول شاشة اختيار المشرف إلزامية، والمشرف الحالي (قدري لمنصور) محدد مسبقًا. الاختيار ينفَّذ على الخادم (`change_supervisor`) فلا تتكرر اليوميات عند الضغط المتكرر.
- **التبويبات حسب الدور**: الأدمن = الكل + «الأدمن» (+ الاستعلامات حيث تُعرض). الرصيص والمشرف = الغرف، اليومية، السجل، الإعدادات. المشرف لا يرى أزرار إضافة/تعديل/حذف الغرف.
- **تبويب الأدمن**:
  1. *الحسابات*: إنشاء، تعديل (الاسم/الدور)، كلمة مرور جديدة، تعطيل/تفعيل، حذف (نهائي إن لم يكن له سجل، وإلا منطقي مع بقاء سجلاته).
  2. *إدخالات بلا مالك*: الإدخالات السبعة القديمة؛ تحديد ثم إسناد لرصيص ومشرف بتأكيد (`assign_entry_owner`).
  3. *كلمة مرور النسخ*: تعيين/استبدال كلمة المرور المستقلة.
- **حماية الخادم** (0004): لا تغيير دور حساب له سجل، لا تعطيل/حذف الحساب لنفسه، لا تعطيل/حذف آخر أدمن نشط، لا حذف نهائي لحساب له سجل. وعمليات الحسابات تُسجَّل باسم الأدمن المنفّذ الفعلي.
- الجلسة تنتهي خلال دقيقة من تعطيل الحساب (والبيانات تُحجب فورًا عبر RLS).

## خطوات التشغيل
1. شغّل `0004_accounts_admin.sql` بعد 0001–0003 (أو أعد البناء من الصفر).
2. انشر الدالة: `supabase functions deploy admin-users` (المفاتيح تُحقن تلقائيًا؛ مفتاح service لا يدخل التطبيق).
3. في GitHub → Settings → Variables أضف `SUPABASE_URL` و`SUPABASE_ANON_KEY` (مفتاح anon عام بطبيعته). وللتشغيل المحلي:
   `flutter run --dart-define=SUPABASE_URL=... --dart-define=SUPABASE_ANON_KEY=...`
4. `flutter pub get && flutter analyze` ثم جرّب الدخول بالحسابات الثلاثة.

## نتيجة الاختبار
`tests/run_local.sh` على PostgreSQL 16: **98 اختبارًا ناجحًا** (منها 19 جديدة للمرحلة 2: قواعد الحسابات، آخر أدمن، التسجيل باسم الأدمن، إسناد الإدخالات السبعة).

## لم يُختبر (بصراحة)
- كود Flutter **لم يُترجَم ولم يُشغَّل** (لا Flutter SDK في بيئتي ولا وصول لـ pub.dev). فحصت توازن الأقواس وراجعت واجهات supabase_flutter يدويًا، لكن توقّع بضعة أخطاء ترجمة صغيرة: أرسل لي مخرجات `flutter analyze` وأصلحها.
- الدالة `admin-users` تحقّقتُ من صياغتها فقط ولم تُشغَّل على Supabase.
- **تنبيه مهم**: بيانات التطبيق ما زالت محلية (SharedPreferences) حتى المرحلة 3. لذلك حجب التبويبات والأزرار الآن واجهة فقط؛ الفصل الحقيقي بين بيانات الرصيص والمشرفين يبدأ عند ربط الشاشات بـ Supabase في المرحلة 3، حيث تفرضه قاعدة البيانات (اختُبر فعلًا).
