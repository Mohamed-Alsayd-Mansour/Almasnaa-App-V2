# المرحلة 4 — المحادثات، الإشعارات المرتبطة، عرض كمستخدم، الأرشفة على الخادم

## ما الذي أُضيف
| البند | التفاصيل |
|---|---|
| **المحادثات** | فردية (محادثة واحدة لكل زوج) ومجموعات. أيقونة 💬 في شريط التطبيق مع عدّاد غير المقروء. لا تغيير في تبويبات الأدوار. |
| **الرسائل** | نص (حتى 4000 حرف)، رسالة صوتية، صورة، فيديو، PDF، DOCX. المرفق الواحد لكل رسالة، ومعه نص اختياري. |
| **@الإشارات** | اكتب `@` فتظهر أسماء المستخدمين النشطين. تُخزَّن الإشارة **بمعرّف المستخدم** لا بالاسم، ويصل إشعار «أشار إليك» لا يتكرر أبدًا. |
| **الإشعارات** | الضغط على إشعار تغيير في إدخال غرفة يفتح **السجل المرتبط** وحده في تبويب السجل (يُلغى بزر مسح الفلاتر). والضغط على إشعار إشارة يفتح **المحادثة عند الرسالة** ويبرزها. |
| **عرض كمستخدم** | للأدمن: قائمة الحساب ← «عرض كمستخدم…». تتغير التبويبات والبيانات المعروضة لنطاق ذلك المستخدم. |
| **الأرشفة على الخادم** | Edge Function `github-archive` + تبويب «الأرشفة» للأدمن. الرمز لا يمر عبر التطبيق إطلاقًا. |
| **حذف الأسماء فقط** | خيار 1.0 في الإعدادات (أدمن + كلمة مرور النسخ). يمسح قوائم الأسماء ويُبقي الغرف واليوميات والإدخالات. |

## الإعداد (مرة واحدة)

1. **قاعدة البيانات**: نفّذ `supabase/migrations/0006_phase4_chat_archive.sql` (SQL Editor أو `supabase db push`).
   يُنشئ جداول المحادثات، bucket خاص باسم `chat-attachments`، سياسات Storage، ويضيف الجداول للمزامنة اللحظية.
   > إن رفض Supabase إنشاء سياسات `storage.objects` من SQL Editor، أنشئ السياسات الثلاث (`chat_files_select/insert/delete`) من *Storage ← Policies* بنفس التعريفات الموجودة في الملف.
2. **الأرشفة** (اختياري لكنه موصى به):
   - أنشئ رمز GitHub **fine-grained** على مستودع الأرشفة فقط، بصلاحية *Contents: Read and write*.
   - اضبط أسرار الدالة (على الخادم فقط):
     ```bash
     supabase secrets set GITHUB_ARCHIVE_TOKEN=github_pat_xxx ARCHIVE_CRON_SECRET=$(openssl rand -hex 32)
     supabase functions deploy github-archive
     ```
     أو أضف `ARCHIVE_GITHUB_TOKEN` و`ARCHIVE_CRON_SECRET` كأسرار GitHub Actions ويقوم workflow `deploy-github-archive.yml` برفعها.
   - للجدولة اليومية أضف في GitHub: متغير `SUPABASE_URL` وسر `ARCHIVE_CRON_SECRET` (نفس القيمة). ملف `archive-github.yml` يستدعي الدالة يوميًا.
   - من التطبيق: الأدمن ← «الأرشفة» ← أدخل `owner/repo` والفرع والمسار ← «اختبار وحفظ» (لا يُحفظ الإعداد إلا بعد نجاح الاتصال) ← «أرشفة الآن».
3. **التطبيق**: `flutter pub get`. أُضيفت الحزم `record` و`audioplayers` و`path_provider` و`cross_file`، وصلاحية الميكروفون في Android/iOS. على الويب يطلب المتصفح إذن الميكروفون عند أول تسجيل (يتطلب HTTPS).

## قرارات التصميم (للمراجعة)
- **خصوصية المحادثات**: العضوية فقط تمنح القراءة، **حتى الأدمن** لا يقرأ محادثات لا يشارك فيها (الأدمن يستطيع إضافة أعضاء لأي مجموعة). إن أردتَ أن يرى الأدمن كل المحادثات فهو تعديل سياسة واحدة في SQL.
- **الإشارة لمن ليس في المحادثة**: يصله إشعار باسم المرسل **بدون نص الرسالة**، وعند الضغط عليه تظهر «لا تملك صلاحية عرض هذه المحادثة».
- **عدم التكرار**: يُنشئ العميل معرّف الرسالة والمرفق مرة واحدة، والدالة `chat_send` تتجاهل أي إعادة لنفس المعرّف. لذا إعادة المحاولة بعد انقطاع الشبكة آمنة، ولا يتكرر إشعار الإشارة.
- **التحقق من المرفقات في الخادم**: نوع الملف وحجمه يُقرآن من بيانات Storage نفسها (وليس مما يدّعيه العميل)، ويُرفض أي نوع/حجم غير مسموح. الحدود: صورة 10MB، صوت 15MB، PDF/DOCX 20MB، فيديو 50MB.
- **الروابط**: الـ bucket خاص؛ يُولَّد رابط موقّع لمدة ساعة عند العرض فقط، ويصدره Storage لأعضاء المحادثة وحدهم.
- **عرض كمستخدم**: لا انتحال هوية. تُرسل ترويسة `x-view-as` مع الطلبات، ولا يعتد بها الخادم إلا لأدمن نشط ولغرض واحد: أن يسجّل `audit_log` المنفّذ الحقيقي (الأدمن) والمستخدم المستهدف (`view_as_id/view_as_name`)، ويظهر ذلك في الإشعارات. الصلاحيات الفعلية تبقى صلاحيات الأدمن.
- **الأرشفة**: لا يُرسل commit إن لم تتغير البيانات (بصمة المحتوى)، ويُسلسَل التنفيذ بقفل في قاعدة البيانات (عملية واحدة في وقت واحد، وتُستعاد العملية العالقة بعد 10 دقائق)، وتُعاد المحاولة تلقائيًا عند تعارض الكتابة. رسائل الخطأ المسجلة قصيرة ولا تحتوي الرمز.
